# ADR-002: การเชื่อมต่อข้อมูล PokéAPI (Kanto 151 ตัวแรก) พร้อมภาพ HD Artwork

- **สถานะ:** Accepted
- **วันที่ตัดสินใจ:** 2026-09-24
- **สัปดาห์หลักสูตรที่เกี่ยวข้อง:** สัปดาห์ที่ 6 (REST API และ Networking)

---

## บริบท (Context)
PokéAPI (`https://pokeapi.co/`) มีข้อมูลโปเกมอนมากกว่า 1,000 ชนิดจากหลากหลายเจเนอเรชัน แต่สำหรับแอปพลิเคชันต้นแบบตามหลักสูตร การดึงข้อมูลมอนสเตอร์ทั้งหมดพร้อมกันจะทำให้:
1. ปริมาณการใช้งานเครือข่ายและแรมสูงเกินความจำเป็น
2. ผู้ใช้ต้องรอดาวน์โหลดข้อมูลนาน
3. ประสบการณ์ผู้ใช้คล้ายคลึงกับ Pokémon GO ในยุคแรกเริ่ม (Kanto Region) ที่คนคุ้นเคยมากที่สุด

## การตัดสินใจ (Decision)
1. **กำหนดขอบเขตข้อมูลเป็น Generation 1 (151 ตัวแรก, Kanto Region):**
   - ดึงข้อมูลผ่าน Endpoint: `https://pokeapi.co/api/v2/pokemon?limit=151`
2. **เลือกใช้ภาพ Official Artwork ความละเอียดสูง:**
   - ใช้ภาพจาก `sprites.other['official-artwork'].front_default` เพื่อให้ภาพคมชัดระดับ HD สวยงามบนหน้าจอ Retina Display
3. **การออกแบบ Service Layer (`services/pokeapi.ts`):**
   - มีฟังก์ชันหลัก 2 ตัว: `getPokemonList()` สำหรับหน้าแคตตาล็อก และ `getPokemonDetail(id)` สำหรับหน้ารายละเอียดและสเตตัส
   - มี In-memory Cache เพื่อป้องกันการยิง Request ซ้ำสำหรับตัวที่เคยดาวน์โหลดแล้ว

## ผลลัพธ์และข้อดี (Consequences)
- **ข้อดี:**
  - โหลดรวดเร็ว ประหยัด Bandwidth และหน่วยความจำของอุปกรณ์
  - มีข้อมูลสเตตัส (HP, Attack, Defense, Speed, Types) ครบถ้วนตามมาตรฐาน
  - ตอบโจทย์เนื้อหาการใช้งาน `fetch`, `async/await`, และ `try/catch` ของสัปดาห์ที่ 6
- **ข้อพิจารณา:**
  - โปเกมอนที่ดึงมาจะเป็นชุด Gen 1 เท่านั้น หากต้องการขยายเป็น Gen 2+ ในอนาคต สามารถปรับพารามิเตอร์ `limit` หรือเพิ่มระบบ Pagination ได้
