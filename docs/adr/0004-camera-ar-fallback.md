# ADR-004: สถาปัตยกรรมโหมดจับโปเกมอน (AR Camera ควบคู่ Classic Field Fallback)

- **สถานะ:** Accepted
- **วันที่ตัดสินใจ:** 2026-09-24
- **สัปดาห์หลักสูตรที่เกี่ยวข้อง:** สัปดาห์ที่ 9 (Camera, Image และ Permissions)

---

## บริบท (Context)
ฟีเจอร์สำคัญของ Pokémon GO คือการเปิดกล้องและเห็นโปเกมอนปรากฏตัวอยู่ในโลกจริง (Augmented Reality - AR) แต่ในการเรียนการสอนและการทดสอบโปรเจกต์:
1. ผู้สอนหรือผู้ตรวจงานมักรันโค้ดบน **iOS Simulator / Android Emulator / Expo Web** ซึ่งไม่มีกล้องจริง
2. บนอุปกรณ์จริง ผู้ใช้อาจปฏิเสธการให้สิทธิ์เข้าถึงกล้อง (Permission Denied)
3. หากแอปบังคับใช้กล้องเพียงอย่างเดียวโดยไม่มีทางเลือกสำรอง แอปจะเกิดข้อผิดพลาดหรือจอดำบน Simulator

## การตัดสินใจ (Decision)
1. **ติดตั้งและใช้งาน `expo-camera`:**
   - ใช้โมดูลกล้องมาตรฐานของ Expo พร้อมจัดการ Permission แบบ Graceful ผ่าน `useCameraPermissions()`
2. **สร้างระบบสลับโหมด Dual-Mode (AR Toggle):**
   - **โหมด AR (AR Mode ON):** แสดงผล Live Camera Preview ผ่าน `<CameraView>` เป็นพื้นหลังฉากจับ
   - **โหมดคลาสสิก (AR Mode OFF / Fallback):** แสดงภาพกราฟิกพื้นหลังสนามหญ้า/ธรรมชาติที่ออกแบบด้วย CSS/SVG
3. **ระบบ Auto-Fallback:**
   - หากตรวจพบว่ากำลังรันบน Simulator หรือไม่ได้รับอนุญาตให้ใช้กล้อง แอปจะสลับไปโหมดคลาสสิกโดยอัตโนมัติ พร้อมสวิตช์ให้ลองเปิดใหม่ได้ตลอดเวลา

## ผลลัพธ์และข้อดี (Consequences)
- **ข้อดี:**
  - ตอบโจทย์เนื้อหาสัปดาห์ที่ 9 (การขอสิทธิ์กล้อง, การเรนเดอร์ CameraView, การทำ UI Overlay)
  - ป้องกันข้อผิดพลาดจอแครชหรือจอดำ 100% บนเครื่องจำลอง (Simulator-friendly)
  - ประหยัดพลังงานแบตเตอรี่ในกรณีที่ผู้ใช้ปิดกล้องเล่น
- **ข้อพิจารณา:**
  - การจับตำแหน่งโปเกมอนกับโลกจริงเป็นการจำลองแบบ Floating Sprite กึ่งกลางจอ ไม่ได้ใช้ระนาบ LiDAR/ARKit เต็มรูปแบบ ซึ่งเหมาะสมกับระดับความซับซ้อนของ Expo Go
