Styling และ Responsive Mobile UI

Tokens & Dynamic Layout
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: ทำ Responsive Grid สลับ 1 หรือ 2 คอลัมน์ด้วย useWindowDimensions()
  • 4 สถานะของรายการ: Loading, Empty, Error, และ Ready
  • Safe Area: เนื้อหาไม่ทับ Notch และ Home Bar ด้วย react-native-safe-area-context
  • Accessibility: ปุ่มมี Touch Target อย่างน้อย 44×44 pt
⚡ การประยุกต์ใช้ใน Pokémon GO
  • Responsive Multi-Grid:
    • มือถือ: 2 คอลัมน์ (แสดงรูปตัวโต ชัดเจน)
    • แท็บเล็ต/เว็บ: 4 คอลัมน์ (คำนวณผ่าน width >= 720 ? 4 : 2)
  • Pokémon Design Tokens: โทเค็นสี 18 ธาตุ (Fire, Water, Grass...) พร้อมโหมด Light/Dark
  • Web Mobile Container: คุมหน้าจอบน Browser ไม่ให้บวม ล็อค Max-width 430px กึ่งกลางจอ
  • Empty State: PokemonEmptyState แสดงปุ่มล้างตัวกรองและปุ่มพาไปจับ

Forms และ State Management

Global Context & Validation
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: ช่องค้นหากิจกรรม, ฟอร์มลงทะเบียนพร้อม Validation
  • State Placement: จัดระดับ Local (useState), Complex (useReducer), Shared (Context)
  • Derived State: ห้ามเก็บผลการกรองซ้ำซ้อนใน state
  • Form Resilience: จัดการคีย์บอร์ดด้วย KeyboardAvoidingView และล็อก Submit
⚡ การประยุกต์ใช้ใน Pokémon GO
  • Global TrainerContext: ดูแล State กลางของทั้งเกม (ระดับเลเวล, EXP, คลังบอล/เบอร์รี่, โปเกมอนที่จับได้) ผ่าน useTrainer()
  • Derived Counts: ใช้ useMemo สรุปจำนวนโปเกมอนตามระดับความหายาก (Common, Rare, Ultra) โดยไม่เก็บ state ซ้ำ
  • Pokedex Filter Bar: Controlled Search Input พร้อมชิปกรอง Gen 1-3 และสถานะ จับแล้ว/ยังไม่จับ
  • Controlled Login Form: ฟอร์มใน login.tsx ดักจับคีย์บอร์ดและล็อกปุ่มระหว่างส่งข้อมูล

REST API และ Networking

External API & Resilient Client
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: เรียก REST API /events และ /events/:id
  • Abstraction: ตรวจสอบ response.ok และ validate JSON runtime ด้วย Type Guards
  • Cancellation: ยกเลิกคำขอผ่าน AbortController เมื่อ Unmount หรือออกจากหน้า
  • UX: ทำ Pull-to-refresh โดยไม่ให้รายการเดิมกระพริบหาย
⚡ การประยุกต์ใช้ใน Pokémon GO
  • PokeApiClient Singleton: เชื่อมต่อ PokéAPI ดึงข้อมูลโปเกมอน Kanto 151 ตัว, Official Artwork HD, ค่า Base Stats, และชนิดธาตุ
  • Custom Data Hooks: usePokemonDetail(id) และ usePokedex() ทำหน้าที่แยก Network Logic ออกจากหน้า Screen Shell
  • Offline Fallback Resilience: หาก PokeAPI ตอบสนองช้า หรือผู้เล่นไม่มีเน็ต ระบบจะ Fallback ดึงข้อมูล Metadata จาก pokemon-registry-data.ts ทันที
💻 ตำแหน่งไฟล์ & โค้ดจริง
src/shared/services/pokeapi/client.ts
export class PokeApiClient { async getPokemonDetail(id: number, signal?: AbortSignal) { try { const res = await fetch(`https://pokeapi.co/api/v2/pokemon/${id}`, { signal }); if (!res.ok) throw new Error('Fetch failed'); return await res.json(); } catch (err) { // Fallback สู่ Registry ข้อมูลในเครื่องทันที return getLocalPokemonFallback(id); } } }
🎯 DoD Verification:
✓ Screen ไม่เรียก fetch ตรง (ทำงานผ่าน Service & Hook 100%) ✓ มี Fallback ข้อมูลสำรอง แอปพลิเคชันไม่ Crash เมื่อออฟไลน์ ✓ AbortController ยกเลิก Request เมื่อผู้เล่นกดปิดหน้าจอ

Local Storage และ Offline Applications

Offline Persistence & SQLite
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: เก็บ Favorites ลง AsyncStorage และทำ Event Cache ออฟไลน์
  • Storage Matrix:
    • AsyncStorage: Key/Value ทั่วไป
    • SecureStore: Token และรหัสลับ
    • SQLite: ข้อมูลโครงสร้างตารางสัมพันธ์
  • ความท้าทาย: ปิดเน็ตแล้วเปิดแอปใหม่ ข้อมูลต้องยังอยู่และไม่ Crash
⚡ การประยุกต์ใช้ใน Pokémon GO
  • SQLite Production Database: ใช้ expo-sqlite ผ่าน DatabaseManager สร้างฐานข้อมูลแบบออฟไลน์เต็มรูปแบบ
  • Relational Schema:
    • caught_pokemon: ประวัติโปเกมอนที่จับได้ (ID, ค่า CP, เลเวล, วันที่จับ)
    • trainer_inventory: บันทึกสต็อกบอล (Pokeball, Great, Ultra) และผลเบอร์รี่
    • trainer_profile: สถิติการจับและค่า EXP
  • 100% Offline Gameplay: ปิดเน็ตแล้วยังเปิดดูกระเป๋าและปล่อยโปเกมอนได้

Authentication และ Mobile Security

Secure Sessions & Route Guards
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: บันทึก Token ใน SecureStore และฟื้นฟู Session ตอนเปิดแอป
  • Route Guards: กั้นหน้าด้วย Stack.Protected ใน Expo Router
  • Dev Build: ติดตั้ง expo-dev-client และสร้าง eas.json
  • ความท้าทาย: หน้าจอต้องไม่กะพริบก่อนตรวจสิทธิ์เสร็จ และ Logout ต้องล้างสะอาด
⚡ การประยุกต์ใช้ใน Pokémon GO
  • SecureStore Auth Service: จัดเก็บ Session Token ของเทรนเนอร์ด้วย expo-secure-store ในระดับ Hardware Keychain
  • Protected Game Stack: _layout.tsx ป้องกันไม่ให้บุคคลภายนอกเข้าหน้าแผนที่, กระเป๋า, และสนามจับ หากยังไม่ได้ยืนยันตัวตน
  • Seamless Restoration: ตอนเปิดแอปจะเช็ค Token เงียบๆ หากถูกต้องจะเข้าสู่โลกโปเกมอนทันทีโดยไม่ต้องกรอกรหัสใหม่
  • EAS Development Build: มีไฟล์ eas.json รองรับการสร้าง Native Build

Location และ Native Maps

Geolocation & Procedural Spawning
📋 โจทย์หลักสูตร (Campus Events)
  • โจทย์ตั้งต้น: ขอสิทธิ์ Foreground Location ด้วย expo-location
  • แสดงผลแผนที่: แสดง MapView และปักหมุด Marker สถานที่จัดงาน
  • การแยกแยะข้อมูล: แยก Current User Location ออกจาก Venue Location (ปิด GPS ก็ต้องดูแผนที่งานได้)
  • ความท้าทาย: จัดการค่าพิกัดเริ่มต้น และคุมการซูมแผนที่ไม่ให้กระตุก
⚡ การประยุกต์ใช้ใน Pokémon GO
  • GPS Spawning Radar Engine: ระบบ PokemonSpawnEngine สุ่มเกิดโปเกมอนป่า 15 จุดรอบพิกัดจริงของผู้เล่นตามสมการ Haversine

  • Wild Marker Mechanics:
    • แถบนับเวลาถอยหลัง (Active 60s) ก่อนโปเกมอนหนี
    • ออร่าแสงสีทองส่องประกายเมื่อเป็นตัวหายาก (Ultra Rare)
  • Default Fallback: หากไม่ให้สิทธิ์ GPS จะจำลองพิกัดใจกลางกรุงเทพฯ
